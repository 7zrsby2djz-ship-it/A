## 使用者與設計前提
- 目標：問路、搭公車、確認方向、搭錯車後求助；以及非觀光地點的生活對話（便利商店、居酒屋、麵店、廣播、入場櫃台、買衣服）。N4 文法當骨架，逐步加入接近自然速度的旅遊聽力與高頻口語；JLPT 只當參考。
- Duolingo 約 820 字只代表「接觸過」，不代表聽得懂。不能假設看到認得的字就聽得出來。
- 使用者有心盲症、容易分心、長篇教學容易累。**不要**用「想像畫面」「記憶宮殿」；靠文字、結構、對比、聲音、句塊、真實情境。畫面上可以有看得見的圖卡（有文字，不只靠顏色）。
- 一次一個小任務（約 2–4 分鐘），一次一個問題，詳細說明按需展開。不用倒數、不強調連勝。

## 日文教材格式（`src/data_tasks.js`）
檔案開頭有完整說明，重點如下：

- **句塊** `K(id, 日文, 羅馬拼音, 中文, 類別, 補充?)`：完整的意義單位，例如「向こう側から」「次の205番に」「〜には止まりません」。漢字一律用 `{漢字|かな}` 標讀音（檢查腳本會擋沒標的漢字）。
  - 類別：`q` 對方在問（店員問句）、`concl` 結論、`neg` 否定、`dir` 方向、`place` 地點、`time` 時間、`num` 號碼數字、`cond` 條件、`advice` 建議、`next` 下一步、`reason` 理由、`topic` 主題、`filler` 語氣開場、`ask` 問句、`polite` 回應。
  - `CRIT`（會影響行動的資訊）：對方在問、結論、否定、方向、地點、時間、號碼、建議、下一步。複習優先、答錯才算「關鍵資訊沒抓到」。
- **一句話** = 句塊 id 陣列 `c` + 整句中文 `zh`。日文、拼音、振假名都由句塊自動組成，所以原句、拆解、提示永遠一致。
- **任務** `T({...})`：`dest` 目的地、`setup` 情境、`sim` 查核／模擬說明、`axis` 每一級增加的面向；`levels` 級數（預設 5，生活情境 3）、`group` 分組（交通／生活）、`dk` 任務板第一格標題（預設「目的地」）、`todo0` 一開始的下一步。
- **變體** `V(任務, 級, id, {who, note, tr, setup?}, [節點...])`：第一個節點是起點。`tr:true` 是**遷移檢查**（換了沒聽過的說法），同級的一般變體練過後才會出現。
- **節點**：
  - `say` 你先開口：`intent` 要表達的意思、`skel` 骨架、`c` 參考答案。畫面先讓使用者自己說，再看參考答案（不做語音辨識）。
  - `hear` 對方回答（生活情境可以當第一個節點，代表對方先開口）：`bc:true` 廣播（只能重播、放慢，不能請它簡單說）、`c`、`zh`、`easy`（簡單說法）、`q` 題目、`learn` 確認到的事、`todo` 下一步、`fig` 圖卡、`point` 手勢線索（「あそこ」「あっち」時用）。
  - `act` 你怎麼接：選項 `O(c, 中文, 判定, 說明, next, {do, skel, fix})`。判定 `ok` 能繼續／`part` 需要補充／`bad` 會造成錯誤行動。有 `next` 就走那條分支（錯的選擇會看到後果，再補救）；沒有 `next` 就讓使用者重選。**不會**替使用者自動換成正確答案。`fix:true` 代表確認／求助類的說法。
  - `end` 結局：`res` = `ok` 完成／`slow` 到了但比較慢／`late` 走錯後補救成功。
- **題目** `Q(問題, [正確, 錯1, 錯2], k, ke?)`：`k` 是答案所在的句塊（必須在原句裡）；`ke` 是簡單說法裡對應的句塊。使用者按「簡單一點」後，沒有 `ke` 的題目會跳過；關鍵資訊題目一定要有 `ke`（檢查腳本會擋）。

### 新增一個情境（例如飯店）
1. 在 `data_life.js` 底部 `T({..., group:'生活', levels:3})` 建任務，寫每一級的 `axis`。句塊 id 全部檔案共用，不能重複（建議加情境前綴）。
2. 每一級至少 1 個一般變體＋1 個 `tr` 遷移變體。每一級主要只增加一個面向：句長、新詞、口語縮略、速度或資訊量。先常見禮貌回答，再加少量隨意說法。
3. 每段對話預設 1～2 個新句塊；熟悉的句塊可以重複使用。
4. 合理的確認、問地標、請對方重說都要給 `ok` 或 `part`，不要只有唯一標準答案。
5. 跑 `node tools/validate.js`，再 `./build.sh`。

## 學習流程與判定
開口 → 聽回答 → 回答 1～3 個小問題（一次一題）→ 判斷或求助 → 補問 → 再確認 → 行動結果。

- **提示逐步撤除**（每句自動決定，使用者也可以自己調）：
  - 句子裡有沒見過的句塊 → **全文**（並先列出最多 2 個新句塊）
  - 都見過，但題目的關鍵句塊「聽音」還不熟 → **局部提示**：其他句塊顯示，關鍵句塊遮成「［方向］」「［時間］」
  - 都熟 → **純聽**
  - 使用者可按「給我提示」「顯示全文」「看中文」。使用提示仍算完成學習，只是記成「看字／提示完成」。
- **求助分開三個按鈕**：もう一度（同一句再放一次）／ゆっくり（同一句放慢）／もう少し簡単に（換成簡單說法）。用了不扣分。
- **答錯回饋**不說「你漏聽了」，而是「答案是…，可以先確認這一塊：［句塊］」，並提示可以重說或用「〜ですね」確認。
- **任務板**一直顯示「目的地／已確認／下一步」。中途離開、重新整理、關掉都能接續，首頁顯示一句前情提示。
- **沒有聲音**（裝置不支援語音）時一律顯示文字，記成看字完成，句塊只加「看字」分數，不算聽力。

## 進度（存在 `S.tk`、`S.ck`）
- 每一級分開記：`text` 看字／提示完成、`listen` 純聽完成、`repair` 求助後完成（不看字，但用了重說、簡單說法、確認）、`transfer` 換說法（遷移變體）也聽懂、`later` 隔天再練仍完成。
- **沒有硬性解鎖**：每一級都能直接試。某級有 `listen`／`repair`／`transfer` 就推薦下一級；通過的級數照間隔複習。
- 句塊：`S.ck[id] = {t: 看字紀錄, l: 聽音紀錄, weak}`，兩者分開排程。句塊複習優先考會影響行動的類別；選項從同一類別出（例如時間：「10時20分発」「20分後に」「20分かかります」放在一起比較）。
- 首頁推薦順序：接續中斷的對話 → 句塊複習（≥4 個到期）→ 到期的級數 → 下一個還沒完成的級數（先 1 級的公車、電車、問路，再 2 級…）。

## 耳機模式
- 優先播放**練過的變體**（最近的在前）；沒練過時放第 1 級預習。
- 三種模式：**教學**（先念不熟的句塊，每句「日文→中文→慢速→日文」）、**連播**（正常速度連著播，不重複）、**接話**（輪到使用者時留空，再播參考答案）。中文、循環、停頓長短可調，播放位置會記住。
- 用手機內建語音（Web Speech API）。**只在螢幕亮著、App 在前景時會播**；iPhone 鎖屏或切到別的 App 會停。鎖屏播放**未支援、未實測**。
- 固定音檔：評估過用自行產生的音檔改善背景播放，但目前的開發環境無法安裝日文語音合成工具（套件來源被擋），所以還沒做。之後如果在有語音合成工具的環境，可以為「練過的對話」產生 m4a/mp3，放進 artifact 的檔案或資產，再實際在 iPhone 鎖屏測試。

## 生活情境（第 2 批）
六個情境、各 3 級（一般變體＋換說法變體），重點是**聽懂店員、廣播先說的話**：

|---|---|
| 便利商店 | 袋子、加熱、筷子、集點卡、付款方式、買酒年齡確認、自己在畫面上付款 |
| 居酒屋 | 人數、吧台、先點飲料（「とりあえず生で」）、大小、お通し、問推薦、最後點餐、到收銀台結帳、只收現金 |

| 車內・車站廣播 | 下一站與開門側、誤點、進站、轉座椅、大雪停駛改搭巴士、東京停駛改搭其他路線 |
| 入場櫃台 | 錢湯毛巾與洗髮精、溫泉鞋櫃鑰匙、會員制場所第一次辦會員、星期三泳裝日（穿泳裝入場免費）、手環記帳 |

- **關鍵字策略**：一個關鍵字＋問的語氣（「洗濯機？」「全部普通で」「初めてです」）判為 `ok`。

## 五十音（假名 → 聲音 → 熟悉的單字 → 意思）
- 入口：日文頁、首頁的「五十音」卡片（練五個／假名表）。程式 `src/kana.js`，資料 `kana-rebuild/generated/kana-data.js`（建置時內嵌，手機不連網）。企劃與資料契約見 `kana-rebuild/`。
- 平假名／片假名／混合三模式；每格最多 4 個代表詞（正常寫法＋讀音高亮＋繁中），先顯示兩個，其餘可展開。少見字首保持合理數量。「這個詞我不熟」會把例子換到後面；單字找字輪替不同詞，答錯重出保留原詞。
- 一輪最多 5 個字、約 15 步：新字先看學習卡，熟過的字先「看字自評」，再出 2 題（聽音選字／讀音找字／平片配對）。混合模式第二題交替配對與單字找字，讓擴充詞進入短練習。答錯隔兩題再出，一輪最多再一次。
- 拼音預設關（不跟著原本課程的讀音設定）；單張「看拼音」換題就收起；看拼音或全域開拼音的題目記成「有提示」，不算獨立通過。
- 清音使用 `generated/kana-audio.js` 的 44 個真人 MP3（公共領域，直接內嵌，可離線）；整詞保留 Web Speech。錄音要成功結束（ended）才可作答，失敗／逾時可重試或「改看字」（有提示，不加聽音分）。切換會停止播放，過期回呼被忽略。
- 進度在 `S.kana`（隨主存檔）；`hira:e`、`kata:e` 分開記，四種能力（看字、聽音、平片配對、單字找字）分開記。兩個不同日期無提示答對才顯示「熟」。舊存檔沒有或只有部分 `kana` 時會自動補齊，不動其他紀錄。
- 特殊字：ん 用字中／字尾、を 用「水をください」、ム 保留 ハム 字中例，也新增 ムービー／ムード 字首例、ヲ 只配對認識；不出 ん／を 的聽音題，お 的題目不放 を 當錯誤選項。濁音詞（でんち、グレー）列在「全部代表詞」最後，下一版再練。
- 建置：`./build.sh` 會自動重建教材與音訊包，再組成單檔。正常建置不連網、不需 ffmpeg。
- 測試：`node tools/test-kana.cjs`（Node Playwright）涵蓋新代表詞輪替、真人錄音事件、舊存檔／接續、360／390／430 深淺色，並實際解碼 44 個 MP3 和離線播放。原回歸 `python3 tools/test-kana.py` 也保留；真機聽感另行驗收。

## 小店遊戲（你是日本小店的店長）
- 入口：首頁、日文頁的「小店遊戲」卡片。檔案：`src/data_game.js`（店、話題、客人回答）、`src/game.js`（遊戲程式）。
- 三家店：便利商店 → 居酒屋（累積 10★）→ 拉麵店（累積 22★）。一天 5 位客人，約 3 分鐘。
- 玩法：按鈕是店員說的日文（直接用對話教材的句塊）。點按鈕先跳出讀音、發音、中文，再按「說這句」。客人用日文回答，你判斷「要／不要」或選選項。問錯、順序錯、漏問會扣客人耐心；全對 3★。
- 熟練模式（點了直接說，多 50 円）、只聽模式（客人的話先不顯示）。每開店 2 天升一級：第 2 級客人會主動先說，第 3 級說法變口語（例如「あ、いいです」＝不用）。
- 帶回對話：遊戲裡出現的句塊記成「見過」，對話裡的提示會變少；聽錯的句塊標成不熟，排進句塊複習。打烊畫面直接推薦對應的對話（便利商店→便利商店・結帳、居酒屋→居酒屋、拉麵店→麵店）。
- 客人臉孔的畫法改寫自《坊市掌櫃》倉庫的 portrait 表情系統（只借程式，沒用它的劇情資料）。
- 新增遊戲內容：在 `data_game.js` 的 `GSHOP` 加話題，`GGEN` 決定每位客人要什麼；跑 `node tools/validate.js` 會檢查句塊是否存在。

## 存檔
- `localStorage`（key：`bnk-state-v1`）；在 Claude artifact 裡登入時也存到使用者帳號（只有本人看得到）。
- 欄位定義在 `app.js` 的 `DEF()`。新增欄位加在 `DEF()`，舊存檔會自動補上。
- 舊版對話進度（`S.dlg` 的「通過」）會轉成新版的「純聽完成」（`migrateOldDlg`）；舊版單字卡 `S.jpw` 保留在「句塊」分頁下方。讀音設定從舊的 `romaji` 轉成 `read`（`furi`／`ro`／`both`／`none`）。
