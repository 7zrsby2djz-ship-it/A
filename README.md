# 按鈕與積木

個人用的 iPhone 學習網頁 App。
- **英文**：看懂 Claude／AI 工具介面上的英文（按鈕、權限、錯誤訊息），重點是相似字比較、貼上查字。
- **日文**：去日本獨旅時能**把一段對話走完**——先開口，聽懂日本人的自然回答，卡住時知道怎麼問下去。

## 另外的獨立工具：聽懂一句

[開啟／下載口語聽力單檔](listening-jp/index.html) · [教材與開發說明](listening-jp/README.md)

從零開始的口語聽力：24 個小課、48 句，以及 36 個補充查詞條目（成人語境詞義另列）。它有獨立的程式、教材、入口和存檔，不讀寫下方交通／英文 App 的進度。GitHub 的檔案頁是原始碼預覽；下載 HTML 後用瀏覽器開啟，或由靜態伺服器提供 `listening-jp/` 目錄。

建置這個工具：`node listening-jp/validate.js && node listening-jp/build.js`。以下說明仍是原本的交通／英文 App。

## 使用者與設計前提
- 目標：問路、搭公車、確認方向、搭錯車後求助。N4 文法當骨架，逐步加入接近自然速度的旅遊聽力與高頻口語；JLPT 只當參考。
- Duolingo 約 820 字只代表「接觸過」，不代表聽得懂。不能假設看到認得的字就聽得出來。
- 使用者有心盲症、容易分心、長篇教學容易累。**不要**用「想像畫面」「記憶宮殿」；靠文字、結構、對比、聲音、句塊、真實情境。畫面上可以有看得見的圖卡（有文字，不只靠顏色）。
- 一次一個小任務（約 2–4 分鐘），一次一個問題，詳細說明按需展開。不用倒數、不強調連勝。

## 日文教材格式（`src/data_tasks.js`）
檔案開頭有完整說明，重點如下：

- **句塊** `K(id, 日文, 羅馬拼音, 中文, 類別, 補充?)`：完整的意義單位，例如「向こう側から」「次の205番に」「〜には止まりません」。漢字一律用 `{漢字|かな}` 標讀音（檢查腳本會擋沒標的漢字）。
  - 類別：`concl` 結論、`neg` 否定、`dir` 方向、`place` 地點、`time` 時間、`num` 號碼數字、`cond` 條件、`advice` 建議、`next` 下一步、`reason` 理由、`topic` 主題、`filler` 語氣開場、`ask` 問句、`polite` 回應。
  - `CRIT`（會影響行動的資訊）：結論、否定、方向、地點、時間、號碼、建議、下一步。複習優先、答錯才算「關鍵資訊沒抓到」。
- **一句話** = 句塊 id 陣列 `c` + 整句中文 `zh`。日文、拼音、振假名都由句塊自動組成，所以原句、拆解、提示永遠一致。
- **任務** `T({...})`：`dest` 目的地、`setup` 情境、`sim` 查核／模擬說明、`axis` 每一級增加的面向。
- **變體** `V(任務, 級, id, {who, note, tr, setup?}, [節點...])`：第一個節點是起點。`tr:true` 是**遷移檢查**（換了沒聽過的說法），同級的一般變體練過後才會出現。
- **節點**：
  - `say` 你先開口：`intent` 要表達的意思、`skel` 骨架、`c` 參考答案。畫面先讓使用者自己說，再看參考答案（不做語音辨識）。
  - `hear` 對方回答：`c`、`zh`、`easy`（簡單說法）、`q` 題目、`learn` 確認到的事、`todo` 下一步、`fig` 圖卡、`point` 手勢線索（「あそこ」「あっち」時用）。
  - `act` 你怎麼接：選項 `O(c, 中文, 判定, 說明, next, {do, skel, fix})`。判定 `ok` 能繼續／`part` 需要補充／`bad` 會造成錯誤行動。有 `next` 就走那條分支（錯的選擇會看到後果，再補救）；沒有 `next` 就讓使用者重選。**不會**替使用者自動換成正確答案。`fix:true` 代表確認／求助類的說法。
  - `end` 結局：`res` = `ok` 完成／`slow` 到了但比較慢／`late` 走錯後補救成功。
- **題目** `Q(問題, [正確, 錯1, 錯2], k, ke?)`：`k` 是答案所在的句塊（必須在原句裡）；`ke` 是簡單說法裡對應的句塊。使用者按「簡單一點」後，沒有 `ke` 的題目會跳過；關鍵資訊題目一定要有 `ke`（檢查腳本會擋）。

### 新增一個情境（例如餐廳）
1. 在 `data_tasks.js` 底部 `T({...})` 建任務，寫 1–5 級的 `axis`。
2. 每一級至少 1 個一般變體＋1 個 `tr` 遷移變體。每一級主要只增加一個面向：句長、新詞、口語縮略、速度或資訊量。先常見禮貌回答，再加少量隨意說法。
3. 每段對話預設 1～2 個新句塊；熟悉的句塊可以重複使用。
4. 合理的確認、問地標、請對方重說都要給 `ok` 或 `part`，不要只有唯一標準答案。
5. 跑 `node tools/validate.js`，再 `./build.sh`。

## 學習流程與判定
開口 → 聽回答 → 回答 1～3 個小問題（一次一題）→ 判斷或求助 → 補問 → 再確認 → 行動結果。

- **提示逐步撤除**（每句自動決定，使用者也可以自己調）：
  - 句子裡有沒見過的句塊 → **全文**（並先列出最多 2 個新句塊）
  - 都見過，但題目的關鍵句塊「聽音」還不熟 → **局部提示**：其他句塊顯示，關鍵句塊遮成「［方向］」「［時間］」
  - 都熟 → **純聽**
  - 使用者可按「給我提示」「顯示全文」「看中文」。使用提示仍算完成學習，只是記成「看字／提示完成」。
- **求助分開三個按鈕**：もう一度（同一句再放一次）／ゆっくり（同一句放慢）／もう少し簡単に（換成簡單說法）。用了不扣分。
- **答錯回饋**不說「你漏聽了」，而是「答案是…，可以先確認這一塊：［句塊］」，並提示可以重說或用「〜ですね」確認。
- **任務板**一直顯示「目的地／已確認／下一步」。中途離開、重新整理、關掉都能接續，首頁顯示一句前情提示。
- **沒有聲音**（裝置不支援語音）時一律顯示文字，記成看字完成，句塊只加「看字」分數，不算聽力。

## 進度（存在 `S.tk`、`S.ck`）
- 每一級分開記：`text` 看字／提示完成、`listen` 純聽完成、`repair` 求助後完成（不看字，但用了重說、簡單說法、確認）、`transfer` 換說法（遷移變體）也聽懂、`later` 隔天再練仍完成。
- **沒有硬性解鎖**：每一級都能直接試。某級有 `listen`／`repair`／`transfer` 就推薦下一級；通過的級數照間隔複習。
- 句塊：`S.ck[id] = {t: 看字紀錄, l: 聽音紀錄, weak}`，兩者分開排程。句塊複習優先考會影響行動的類別；選項從同一類別出（例如時間：「10時20分発」「20分後に」「20分かかります」放在一起比較）。
- 首頁推薦順序：接續中斷的對話 → 句塊複習（≥4 個到期）→ 到期的級數 → 下一個還沒完成的級數（先 1 級的公車、電車、問路，再 2 級…）。

## 耳機模式
- 優先播放**練過的變體**（最近的在前）；沒練過時放第 1 級預習。
- 三種模式：**教學**（先念不熟的句塊，每句「日文→中文→慢速→日文」）、**連播**（正常速度連著播，不重複）、**接話**（輪到使用者時留空，再播參考答案）。中文、循環、停頓長短可調，播放位置會記住。
- 用手機內建語音（Web Speech API）。**只在螢幕亮著、App 在前景時會播**；iPhone 鎖屏或切到別的 App 會停。鎖屏播放**未支援、未實測**。
- 固定音檔：評估過用自行產生的音檔改善背景播放，但目前的開發環境無法安裝日文語音合成工具（套件來源被擋），所以還沒做。之後如果在有語音合成工具的環境，可以為「練過的對話」產生 m4a/mp3，放進 artifact 的檔案或資產，再實際在 iPhone 鎖屏測試。

## 存檔
- `localStorage`（key：`bnk-state-v1`）；在 Claude artifact 裡登入時也存到使用者帳號（只有本人看得到）。
- 欄位定義在 `app.js` 的 `DEF()`。新增欄位加在 `DEF()`，舊存檔會自動補上。
- 舊版對話進度（`S.dlg` 的「通過」）會轉成新版的「純聽完成」（`migrateOldDlg`）；舊版單字卡 `S.jpw` 保留在「句塊」分頁下方。讀音設定從舊的 `romaji` 轉成 `read`（`furi`／`ro`／`both`／`none`）。

## 驗證方式（這一版做過的）
- `node tools/validate.js`：37 個變體、290 個句塊；檢查振假名、題目答案在原句、簡單說法保留關鍵資訊、所有分支都走得到結局。
- 瀏覽器自動測試（iPhone 390×844）：425 條分支路徑全部走到結局；答錯、看提示、求助（三種）、簡單說法、搭錯車補救、中斷後重新整理接續、沒有聲音、舊存檔轉換、句塊複習、耳機模式三種模式與位置記憶、深淺色、無橫向捲動。
- 未實測：真實 iPhone 上的語音品質、鎖屏播放。
