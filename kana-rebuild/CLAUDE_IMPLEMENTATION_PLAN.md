## 1. 要解決的問題與核心學法

使用者以前常開著羅馬拼音學日文，已接觸一些單字和兩套假名，但字形辨識零散。他想用自己現有的日文詞彙重新建立假名辨識，像 A → Apple。核心固定為：

**假名 → 聲音 → 已接觸或值得學的單字 → 意思。**

看得懂中文意思、認得漢字、教材有收錄、Duolingo 顯示學過，全部只能當接觸證據，不能直接當作「能讀假名／能聽懂」的進度。

原始需求必須保留：

- 在同一個 App 裡新增模組，主要供 iPhone 使用。
- 假名表點開後有 1～2 個代表詞，可播放假名與整詞。
- 平假名／片假名／混合三模式；同音兩套字逐漸連起來，能隨時只練較弱的一套。
- 正常日文寫法與假名讀音並列，依讀音分類。
- 羅馬拼音預設隱藏，能單張暫看，也能全域開關。
- 先用現有 App、已見過的 Duolingo 詞，再補旅行／日常詞，最後才用 N5→N4→N3 擴充。
- 每輪短、一次一題，能中斷、接續；用提示仍是學習。

使用者靠文字、結構、聲音、實際可見的線索學習。不要要求腦內想像圖像或記憶宮殿。可見插圖可選，第一版不依賴圖片製作。

## 4. 假名分類與發音規則

### 正常詞

顯示 `word` 的原本寫法；依 `readingHiragana` 的 `firstKana` 分類。例：駅 → えき → え、仕事 → しごと → し、観光 → かんこう → か。

不要從漢字第一字、羅馬拼音首字母或英文翻譯分類。平片轉換只用於索引與需要顯示的讀音；不把正常詞面「駅」改掉，也不把片假名外來語的正常詞面全改平假名。

正規化使用 NFKC，包括半形片假名與合成濁點。濁音、半濁音、小字、長音不抹掉：グレー 屬 グ／ぐ，電池／でんち 屬 で，不能分進 ク／く 或 て。

### 第一字與第一拍分開

りょこう 的第一個字是 り，第一拍是 りょ；きゃく 第一個字是 き，第一拍是 きゃ。這些詞可以當基本字形的延伸，但不能剪整詞第一拍去教 ri 或 ki。代表詞中的 `head_extension`、`eligibleForAudioHead:false` 已記錄這個限制。第一版的基本聽音播放單獨基本音；整詞播放只做整詞連結。

### 特殊字

| 字 | 教法 | 不可生成的題型 |
|---|---|---|
| ん／ン | 本、日本、パン、コンビニ 高亮字中／字尾；播放整詞。不同前後音會影響實際音色，不把 n 當成固定英文 n | 普通詞首題、從任意 TTS 整詞切出固定 n 音 |
| を | 水をください，突出 を，簡短說明動作對象；常用音 o、內部 ID wo | 要求 を 開頭普通詞；お 與 を 的無情境唯一正解聽音題 |
| ヲ | 在配對關係中可查看，連到 を 的助詞說明；`reference_only` | 硬湊普通代表詞；計入一般字首測驗必答項 |
| ム | 用 ハム 的字中位置，標「找出字裡的 ム」 | 把 ハム 當成 ム 開頭的詞 |
| は／へ | 基本例子 はい／部屋 教 ha／he；助詞用法在說明折疊區教 wa／e | 不帶上下文就把 は＝wa 或 へ＝e 當作清音表的唯一基本讀法 |

第一版學基本格，**代表詞裡可以自然含濁音、促音、長音或拗音**。例如 切符／きっぷ、カード、メニュー；先聽整詞，不要求額外小字考試。濁音、半濁音、小字、長音的完整表與獨立考核留到下一版。

## 6. 學習流程

### 自選與短練習

首頁顯示「平／片／混合」與假名表。使用者可點任意格，沒有硬性解鎖。主行動「練五個」，優先：中斷接續 → 到期／最近混淆的格 → 少量新格。最多五個目標格，約 2～4 分鐘；使用者可提前結束。

預設模式採混合，但以同聲音的兩套字建立連結；「只練平」「只練片」隨時切換。在混合教學卡可顯示小一號的另一套字，但在正式辨識題中不能用另一套字提示答案。

每個目標先學習卡，再做 1～2 個簡單問題；第一版整輪約 8～10 題即可。先熟悉本輪內容，題目的錯誤選項優先取本輪／已練格和少量常見混淆字，避免丟四個全沒教過的字。

### 卡片

頂部大假名與「聽假名」；中間代表詞正常日文、假名讀音、繁中、讀音中目標假名高亮；各詞有「聽單字」。詳細語義／特殊字說明折疊展開。來源只用小標或展開資訊，不讓版本、雜湊等工程資訊佔學習畫面。

例：え → 駅 → えき → 車站。點發音先聽基本音，再自己按整詞。單字裡的目標字以可見字重／底線等標記，也有語意標籤，不只靠顏色。

### 題型與計分含義

| 題型 | 問法與答案 | 記錄 |
|---|---|---|
| 音 → 字 | 播放基本音，明確指定「選平假名」或「選片假名」；3 個字形選項 | `hear` |
| 字 → 音 | 看字，自行讀／想一下，再揭曉並播放；可自評「會／需提示」。不做語音辨識，不能當成客觀發音通過 | `view`，自評與客觀題分開 |
| 讀音 → 目標字 | 駅／えき，找第一個假名；特殊字改成找字中／字尾／助詞 | `wordLink` |
| 平片配對 | 顯示 え，從片假名找 エ，或反向；3 個不同聲音的字形 | `pair` |

不使用「え 的聲音是？ e／ka／su」作為核心題，避免又把羅馬字變成主要練習。字→音的客觀選音方式可後續實作；第一版以音→字做聽音證據。

聽音混合模式要避免兩個正解：同一道題指定目標文字，或者同音兩套文字都可接受。第一版採指定文字並只給該套選項。お／を、同音濁音等將來也需用情境或字形區分，不能直接當彼此的唯一錯誤音值。

每題先提交再看答案；答後顯示正字、基本音與熟悉詞。不要點錯立即跳下一題。答錯的格在至少隔兩個其他題後再出現，最多本輪兩次，避免無限重考。

### 拼音提示

五十音模組自有設定，初次預設關；不讀取原本課程可能已開啟的 `S.settings.read` 當預設。全域開只影響五十音；卡片或題目「看拼音」可暫看，換卡／換題收起。

開啟全域拼音仍能學習。使用拼音的題記為 `assisted`，不計為獨立辨識通過；可以稍後再做無提示版本。重播同一音、放慢不算羅馬提示，但記錄重播／速度，留作觀察。

正式題目作答前，不在副標、aria-label、tooltip、隱藏文字或上個卡片殘留區直接洩漏羅馬答案。無障礙名稱只描述功能，如「重播題目發音」；揭曉後才增加答案資訊。

## 7. 手機 UI

沿用 App 的淺／深色、字體、圓角和按鈕樣式。繁中介面；假名文字用適合日文字形的字體。每個表格按鈕能單手點，大致 ≥44×44 px；完整五欄表在 360～430 px 螢幕內不橫向捲動。

推薦手機配置：上方小標與返回；模式切換；「繼續／練五個」主按鈕；五欄基本表。や行與わ行空位留白。混合表可同格顯示兩套字，單格點入可切當次目標文字；平片進度各自顯示，不能只顯示一個合計百分比。

學習卡只保留大假名、代表詞、讀音、繁中與發音／拼音／下一個。避免卡片一開始就放長文法說明。練習一次一題，答案按鈕足夠大，底部考慮 iPhone safe area。

表格狀態用「未練／需複習／已練」加簡單符號／文字；細部可看「看字、聽音、配對」。只看過一次卡片，不顯示全部熟練或金色滿格。沒有倒數、硬性每日連勝要求或強制重頭學。

## 8. 發音與失敗降級

沿用 Web Speech，`ja-JP`，預設清楚的正常速度（例如約0.9），再聽可約0.75～0.8；只在使用者點擊之後播放。第一版不承諾鎖屏／背景播放。若現有全域速率與模組速率相乘，避免慢速再被疊成極不自然速度。

播單字時用已確認的 `reading`／`speechText`，不要讓 TTS 對漢字多音自選；無任何羅馬文字丟進日語 TTS。基本音用假名。ん 用整詞，を 可播放整句並說明 o；不能用基本音播放模式隨便切長音或 n 的音訊。

新模組的音訊成功必須分清 `onend` 與 `onerror`。目前共用 `speak()` 把兩者接到同一回呼，Claude 可以加專用包裝／事件結果或做相容擴充；現有課程的回呼行為不被破壞。

音→字題只在成功開始播放、成功結束，且使用者未揭曉文字／拼音之後才可增加 `hear` 的客觀無提示正確數。沒有語音功能、失敗、取消或明確按「沒聲音」時，給重試／改看字，這題只記看字學習，不增加聽音證據。`voiceschanged`／可用日語聲音延遲載入要處理；平台 API 有存在不代表聲音真的可用。

離開模組、換題、快速連點新發音時取消前段播放；用播放／題目識別碼忽略過期回呼，避免上一題 onend 把下一題標成播過。聽音題作答前可用文字說「先播放題目」，不能默默考沒有播成功的音。

## 9. 進度保存與舊資料相容

建議把五十音學習放在主 `S.kana`，使用現有 `persist()`，讓 localStorage 與已有帳號存檔能力沿用。口語仍使用原獨立流程。Claude 也可選擇合理的獨立模組封裝，但需要同樣保存與舊資料相容。

建議資料形狀（可調整但保持穩定 ID）：

```js
S.kana = {
  v: 1,
  prefs: {script:'mixed', romaji:false},
  cards: {
    'hira:e': {
      view: {attempts:0, correct:0, assisted:0, selfRated:0, due:0},
      hear: {attempts:0, correct:0, assisted:0, due:0},
      pair: {attempts:0, correct:0, assisted:0, due:0},
      wordLink: {attempts:0, correct:0, assisted:0, due:0},
      seen: false, lastSeen:0, lastWrong:0
    }
  },
  wordFamiliarity: {},
  active: null
};
```

`hira:e` 與 `kata:e` 分開；`wo` 和 `o` ID 分開；詞 ID 明確且穩定，不按排序索引或改動中文重新生成 ID。

在 `DEF()` 補預設，但舊 `migrate()` 主要補頂層，已存在的部分 `kana` 物件還需巢狀補全，不能假設所有欄位都在。不清除 `S.tk`、`S.ck`、`S.jpw`、英文紀錄、遊戲、口語、設定或收藏，也不以假名學習反向清零其他課程。資料在教材裡有出現，不補熟練度。

每次答案後立即保存；`active` 保存本輪目標、題序與當前位置、是否已揭曉／已計分。重新整理後能接續，不重複計分；播放成功狀態不跨頁重載當成新題已播放，接續聽音題需重播。暫時揭曉的拼音不當成全域設定寫入。

第一版用簡單間隔：當輪錯誤稍後再見，無提示正確的格在隔天、數天後再練。可以沿用現有排程方法，不必新建大型 SRS。提示後正確、同一題重選、自評會讀，都不等於第一次獨立通過。達到「熟」的展示標準至少跨兩個日期有無提示正確，且各能力證據分開。

若雲端環境目前可用，五十音應隨主狀態保存；獨立 HTML／一般瀏覽器以本機保存為準，不標榜任意裝置同步。延用原同步衝突策略，此模組不做整套存檔架構重寫。

## 10. 資料更新與建置

1. 修改 `curation.cjs` 代表詞選擇時，重跑 `build-data.cjs` 與 `validate.cjs`。
2. 上游或現有教材來源真的改了，先讀新內容、補必要人工讀音，再更新 `source-lock.json`；雜湊不符不以跳過檢查作解法。
3. 初次整合把資料生成與 UI 來源接入 `build.sh`；內嵌資料在使用它的模組之前，主 `app.js` 仍最後載入。

現成 OpenJLPT 上游快照 `0d1d3410bec90bd4098a7c72de820543cb4f707c`，原始檔包含英文詞義、讀音、部分例句／振假名。第一版內嵌只有已選起步資料與近似等級，沒有全部2,963筆。其餘檔案供 Claude 後續在開發時抓取、審閱、挑選，不是每次手機打開都遠端抓。

## 11. 驗收與必要測試

資料包已通過 `node kana-rebuild/tools/validate.cjs`。施工之後還需驗證真正的畫面、保存與音訊結果，不能以「JS 語法沒錯」當完整驗收。

| 實際操作 | 期望結果 |
|---|---|
| 打開同 App 日文頁，進入五十音再回交通／口語 | 同一根入口、導航正常、原課程與進度仍可用 |
| 初次進入，舊課程原本拼音開 | 五十音仍預設拼音關；舊課程的設定保留 |
| 點 え | 駅、えき、車站；正確高亮 え，可播放基本音與整詞 |
| 開「單張拼音」再換題 | 當張能看，下一張收起；此次記 assisted |
| 全域開拼音再重新打開 | 模組偏好保存；無提示通過不因提示而灌分 |
| 切三模式，點同音兩套字 | 內容與目標文字正確；平片能力各自紀錄 |
| 混合聽音，選項出現同音平片 | 題目指定文字且無雙正解，或兩套皆可接受；不誤判 |
| り 的旅行延伸、ム 的ハム、ん 的日本、を 的句子 | 字形／字中／助詞題型符合資料限制，沒有错误字首音 |
